# 圆角逻辑审查与调整

日期：2026-11-07。基于 v2.2.0 工作区进行静态审查，包含本次修改后的独立复核。未启动应用或执行测试，不能将本记录视为右下角问题的运行验收。包信息见 [validation-history.md](validation-history.md)。

## 覆盖范围

| 对象 | 圆角方式 | 本次结论及处理 |
| --- | --- | --- |
| 普通窗口、设置页、迷你窗口 | 同一自有 HWND 的 DWM 系统圆角 | 保留系统合成，抽取共用入口；初始化、自身分层样式切换与主题／合成变化入口继续保留 |
| 独立容器宿主 | 自有宿主 HWND 的 DWM 系统圆角 | 与主窗口复用入口，补齐主题／合成变化后的请求；先校验宿主身份，再进入标题栏处理 |
| 容器内第三方窗口 | 顶层联动时保存、临时抑制并恢复目标圆角偏好 | 原值可读才写，失败保留恢复责任；嵌入模式不写目标圆角，本轮无需修改 |
| 托盘、普通／迷你列表菜单 | 4 DIP 半径的实际窗口区域 | 缓存自有期望区域及读取区域，每次仍校验实际形状；隐藏状态阻止重新裁圆，恢复失败保留快照供后续清理重试 |
| 标题栏按钮、普通按钮、卡片、选中底色 | GDI+ 圆角路径及 GDI 降级 | 保留各自半径和矩形点击区域；主列表卡片边缘改为物理尺寸直接减边距，卡片半径直接按 DPI 缩放 |
| 输入框、下拉框、复选框 | 共享圆角路径 | 窄尺寸将直径限制到短边，零直径走矩形，拒绝非有限坐标及无效尺寸；保留常规描边、文字和图标行为 |
| 滑条和滚条 | 圆头轨道／手柄及共享圆角绘制 | 滚条移除重复的 GDI+ 实现，复用原点处理、抗锯齿和 GDI 降级；奇偶宽度维持圆头语义 |

## 静态发现与修正

1. 主列表卡片将客户区像素反算逻辑尺寸后再次缩放，任意物理宽高可能发生二次取整；改为从实际右／下边界直接减去缩放后的边距。主卡片与设置卡片分别直接缩放 4 DIP、6 DIP 半径，菜单也先缩放半径再生成直径。
2. 菜单每次前后置布局消息和每项绘制都创建两个区域对象；现在只在首次设置或尺寸／DPI 改变时生成期望形状，读取区域复用。在未发生形状变化的路径不再创建或设置区域，但仍通过 `GetWindowRgn`／`EqualRgn` 检查原生菜单是否覆盖了形状，不能退回仅比较尺寸。
3. 菜单缓存中的区域一直由本程序拥有，需要修改窗口时才复制出独立区域交给 Windows。只在 `SetWindowRgn` 成功后登记修改责任；恢复失败保留原区域快照，随后隐藏通知、菜单循环结束及注销上下文前可再次尝试。持续失败、窗口身份消失或变化不能保证恢复，但不会盲目修改其他窗口。
4. 菜单隐藏前恢复区域时，窗口可能尚为可见。新增独立隐藏 HWND 标记，绘制与普通布局刷新不得重新裁圆；仅明确的显示通知解除标记，销毁时清理。两个 hook 继续只存在于菜单循环，共用重入保护，跨 Win32 调用不持有 `RefCell` 借用。
5. 容器宿主初始化后未重新处理主题／桌面合成变化。现与主窗口复用 DWM 入口，并在标题栏消费消息前重申，不重新执行完整初始化或强制定位，也不增加拖动时的重复设置。
6. 主题绘制的 `SavedDc` 在保存失败时仍通过提前求值创建并析构保护对象；改为成功后才构造。共享路径统一检查尺寸、有限数值和直径上限，减少极窄控件直接降级为 GDI 的情况。

## 核对范围与限制

- 已进行 Rust 格式／语法解析、差异及引用检查，以及菜单资源生命周期、隐藏状态、窗口身份和绘制几何的独立静态复核
- 没有新增依赖、常驻 hook 或定时扫描；没有修改用户配置、第三方窗口恢复逻辑、菜单命令或标题栏点击区域
- DWM 接受圆角偏好不等于实际可见圆角；菜单区域属于整数像素裁剪，其外缘平滑及阴影与 DWM 窗口不同，不能据代码改动保证两者视觉完全一致
- 高 DPI、跨屏、连续打开／关闭菜单、最大化／还原、主题变化、极窄控件及各处四角的实际显示仍需后续获准运行验证；区域对象分配减少是代码路径结论，未进行性能测量

区域副本使用 [`CombineRgn(RGN_COPY)`](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-combinergn)，缓存句柄不交给窗口。自有窗口与菜单的圆角策略参考此前已核对的 [DWM 圆角限制](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners)。
