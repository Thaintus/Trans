## 已修复的问题

### P2：配置加载失败后，退出可能覆盖原损坏文件

- 调用链：`App::new` 在 `Settings::load` 失败时使用默认设置；窗口创建后记住几何，关闭或退出时因几何变化调用 `save_current_settings`。用户即使没有主动保存，也可能用默认值覆盖原文件。
- 修复：[settings.rs](../src/settings.rs) 在保存前读取现存字节；非 UTF-8 或解析失败时，先以 `create_new` 创建独立的 `settings.recovery-*.ini`，完整写入并 `sync_all`、关闭后再进入原有临时文件替换流程。
- 原文件不存在或配置有效时不创建副本；读取或备份失败拒绝覆盖；写入失败尝试删除本次不完整副本，已完成副本不因后续替换失败被删除。
- 新增三个临时目录行为测试的源码，覆盖原字节保留、正常／缺失配置不备份、读取失败早退；本轮没有执行这些测试，也未做磁盘写入或同步故障注入。
- 外部程序在读取与替换之间修改配置仍属于原有并发编辑边界，本轮未引入监控或全局文件锁。

### P2：恢复所属关系时可能误用被复用的窗口句柄

- 原 [window_container.rs](../src/window_container.rs) 仅保存 `original_owner` 的裸 HWND，脱离时通过 `IsWindow` 判断。原所属窗口在托管期间销毁、句柄被其他窗口复用时，会将目标错误归属到新窗口；仅比较 PID/TID 也不能覆盖同线程复用。
- 修复：保存 HWND、PID/TID 和每容器独立属性令牌的 RAII 身份对象，在修改目标前建立，并在可能重入的初始化步骤后再次核对。多个容器共享原所属窗口时，各自使用独立标记；编号检查递增，不回绕复用。
- 脱离仅恢复身份仍匹配的所属窗口，失效时恢复为无所属窗口。原所属窗口无法标记时拒绝启用容器，避免建立无法安全恢复的关系。
- 正常释放、创建失败和回滚沿用现有 Box／Rc 生命周期，只移除仍属于本对象的属性。此次为静态生命周期核对，未进行真实句柄复用或跨进程权限故障实验。

### P2：只隐藏容器任务栏时，整体恢复可能错误隐藏原窗口

- 原 [window_control.rs](../src/window_control.rs) 将任务栏资格检查失败直接视为“原按钮不可见”，随后恢复时据此决定 `AddTab`／`DeleteTab`。有所属窗口但带 `WS_EX_APPWINDOW` 的可见顶层窗口可拥有任务栏按钮，不能把资格未知当作确定不可见。相关契约见 [Microsoft 扩展窗口样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)。
- 修复：删除推测的原可见性字段，使用 `direct_taskbar_hidden` 记录本工具是否实际隐藏过原窗口；宿主隐藏／显示单独更新当前逻辑状态。
- 整体恢复只撤销实际发生过的原窗口隐藏；仅隐藏宿主时不对原窗口执行任务栏操作。
- 取消容器并继续直接模式时，先回到原窗口的操作记录，再应用原宿主的隐藏选择；首次直接隐藏仍执行资格检查。失败时保留实际状态与尚未完成的恢复责任。
- 静态逐支核对了“原窗口隐藏→容器显示→取消容器”“仅隐藏宿主→恢复全部”“仅隐藏宿主→取消容器”和失败重试；未执行 Explorer 或第三方应用的运行验收。

## 已落实的性能优化

- [ui_theme.rs](../src/ui_theme.rs)：名称单元格绘制使用固定 1028 个 UTF-16 字符的栈数组，消除逐行堆分配，保留原读取长度和省略号附加空间。
- 状态标记查询仅在名称列实际绘制时执行，其他 custom-draw 阶段不再查询线程局部 HashMap。
- [app.rs](../src/app.rs)：按钮选中状态未变化时，不再重复写属性及申请重绘。

这些优化消除了源码中可确认的重复工作，未进行性能基准测量，不给出 CPU 或帧率改善数值。保留上一轮取消整窗合成缓冲、滑块状态变化时申请重绘以及布局提交后统一补绘的策略。
